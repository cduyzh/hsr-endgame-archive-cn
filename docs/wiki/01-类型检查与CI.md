# 类型检查与 CI 门禁

> 记录于 2026-09-08，对应提交 `4137bb3`。历史错误清单见 [02-类型错误审计](./02-类型错误审计.md)。

## 结论先说

1. **本仓库没有任何 CI 平台配置** —— 没有 `.github/workflows`、`.gitlab-ci.yml`、`.circleci`、`.travis.yml`、`azure-pipelines.yml`。唯一的自动门禁是 Netlify 的构建命令。
2. **`pnpm typecheck` 在修复前是空转的**，因此那条门禁从来没有做过类型检查。它现在才是真的。

## CI 门禁的实际构成

`netlify.toml:2` 把构建命令定为 `pnpm build`，而 `package.json:8`：

```json
"build": "run-p typecheck test:unit lint build:only"
```

`run-p` 是 `npm-run-all2` 的**并行**执行，任一子任务失败即整体失败。所以部署路径上的检查是：

| 任务 | 命令 | 检查内容 |
| --- | --- | --- |
| `typecheck` | `vue-tsc --noEmit`（`package.json:11`） | 类型 |
| `test:unit` | `vitest run`（`:13`） | 143 个单测 |
| `lint` | `eslint .`（`:12`） | 规则违规（注意：**warning 不会让构建失败**） |
| `build:only` | `vite build`（`:9`） | 打包 |

本地手动部署走 `scripts/deploy-netlify.sh:19`，同样先跑 `pnpm build`，所以两条路径的门禁一致。

已验证：故意留一个 lint error 时 `pnpm build` 退出码为 1，即失败确实会挡住部署。

## `pnpm typecheck` 为什么曾经什么都不检查

`typecheck` 脚本本身（`vue-tsc --noEmit`）看起来没问题，坏在它读取的配置上。修复前的 `tsconfig.json` 是一个 solution 文件：

```jsonc
{ "files": [], "references": [{ "path": "./tsconfig.app.json" }, { "path": "./tsconfig.node.json" }] }
```

`tsc`/`vue-tsc` 只有在 **build 模式（`-b`）** 下才会顺着 `references` 去检查子项目；不带 `-b` 时它读的就是这个 `files: []`，**输入文件集合为空**，于是零错误、零检查、退出码 0。

实测证据：往 `src/` 放一个 `export const broken: number = "no"`，当时的 `pnpm typecheck` 照样通过。

### 修法

收敛成单项目，不再用 solution + references：

- `tsconfig.json:2` → `{ "extends": "./tsconfig.app.json" }`
- `tsconfig.app.json:3` 的 `include` 扩到 `src/**`、`tests/**`、`netlify/functions/**/*.ts`、`vite.config.ts`
- 去掉 `composite`，删除冗余的 `tsconfig.node.json`

这样 IDE、`vue-tsc --noEmit`、`tsc --noEmit -p tsconfig.app.json` 看到的是同一个项目，也堵住了「有人跑 `tsc -b` 结果冒出一串 TS6307 跨项目引用噪音」的坑。

`typecheck` 脚本字符串没变（仍是 `vue-tsc --noEmit`），但语义从「什么都不查」变成「查 4 个目录」。

## 今后的影响

- **类型错误会直接挡住部署**，包括 `tests/**` 与 `netlify/functions/**` 里的 —— 这两处在修复前从未被任何命令检查过。
- 本地跑 `pnpm typecheck` 是唯一能看到这些错误的方式；没有 CI 日志可看，构建失败只会在 Netlify 部署页或本地 `pnpm build` 输出里出现。
- `run-p` 并行意味着 typecheck 的报错会和 vite/vitest/eslint 的输出**交错混排**，排查时先单独跑 `pnpm typecheck`。
- `pnpm build` 里的 `lint` 只拦 error 不拦 warning。当前 warning 为 0（266 条格式 warning 已在 `4137bb3` 用 `--fix` 清零），所以这条暂时不用管。

## 本地命令

```bash
nvm use                 # .nvmrc 固定 Node 24；sync:stages 依赖 --experimental-strip-types
pnpm typecheck          # 单独跑类型检查，输出最干净
pnpm build              # 完整门禁：typecheck + 单测 + lint + 打包
```
